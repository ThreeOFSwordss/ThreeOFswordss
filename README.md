### 🗂️ project philosophy

I prefer documenting projects instead of simply uploading code.

Each project repository is intended to explain:

- what the project is
- what problem it solves
- how it works
- which technologies were used
- what was learned
- and what state the project is currently in

Some projects are complete, some are experiments, and some are still being developed.

The repository should make that clear instead of presenting unfinished work
as something it is not.

---

### 🔒 private & client projects

Some of my projects were developed for private clients, organizations,
or environments where source code and project data cannot be publicly shared.

For these projects, I document the technical idea, architecture,
technologies, workflow and results whenever possible without exposing
confidential information.

No private source code, customer data, datasets or sensitive information
is included in those repositories.
